## 1. จุดขาย

**ประโยคเดียว:** *ทั้งบ้านเปิดแอร์ ต้มน้ำ เป่าผม พร้อมกัน แล้วไฟดับ คุณคือคนเดียวที่ต้องวิ่งไปที่ Panel และหาให้ได้ว่าใครเสียบอะไรไว้ตรงไหน*

| เสา | ทำไมคนต้องเล่น |
| --- | --- |
| **ทุกคนเคยเจอ** | เบรกเกอร์ตัดเพราะเปิดหลายเครื่องพร้อมกันเป็นเรื่องที่คนไทยเกือบทุกบ้านเคยเจอ ไม่ต้องสอน ขำตั้งแต่วินาทีแรก |
| **เป็นนักสืบ ไม่ใช่นักคิดเลข** | เกมจัดสรรทรัพยากรทั่วไปให้ข้อมูลครบ เกมนี้ซ่อนทั้งผังสายไฟ และสิ่งที่เกิดหลังประตูที่ปิด ช่วงสนุกที่สุดคือ "อ๋อ ปลั๊กห้องนอนต่อกับห้องนั่งเล่นนี่เอง" |
| **มองไม่เห็น = ต้องเลือกว่าจะไปดูอะไร** | ตัวละครอยู่ได้ทีละที่ ไปที่ Panel ก็มองไม่เห็นครัว ไปครัวก็สับเบรกเกอร์ไม่ได้ **เปิดประตูทิ้งไว้ ยืนที่ Panel แล้วมองโคมไฟในห้องข้างๆ** คือทักษะที่ผู้เล่นค้นพบเอง |
| **ศัตรูคือครอบครัว** | ไม่มีใครผิด พ่อแค่อยากกินขนมปัง ปู่แค่หนาว แต่รวมกันแล้วบ้านพัง ตรงกับธีม *We* R in Trouble |
| **แพ้แล้วรู้ทันทีว่าทำไม** | `Kettle 6 + Toaster 4 = 10 > 8` แล้วกด R เล่นใหม่ได้ใน 1 วินาที |

**ยืมโครงจาก This War of Mine แต่กลับอารมณ์:** TWoM ใช้ภาพตัดขวางบ้านให้รู้สึกหดหู่และโดดเดี่ยว TRIPPED! ใช้โครงเดียวกันให้รู้สึกวุ่นวาย น่ารัก และกวน

**ยังไม่ได้พิสูจน์:** ความแปลกใหม่เทียบเกมอื่น (ค้นใน itch.io คำว่า "breaker", "fuse box", "power outage") และความสนุกจริงจนกว่าจะเพลย์เทสต์

## 2. ระบบบ้าน ตัวละคร และ Sight

### 2.1 House

House เป็นตารางห้องในภาพตัดขวาง แต่ละห้องมี `floor` (0 = ชั้นล่าง) `x` (เมตร ขอบซ้าย) และ `width` (เมตร)

```
 floor 1   ┌─ Bedroom ───┬─ Bathroom ─┐
           │  [BR1] [BR2]│   [BA1]    │
           ├──────╫──────┴────────────┤        ╫ = Stairs    ║ = Door
 floor 0   │ Kitchen  ║ Living  ║ Laundry [PANEL] │
           └──────────────────────────────────────┘
```

| วัตถุ | ข้อมูล |
| --- | --- |
| Room | `id`, `name`, `floor`, `x`, `width` (4 / 6 / 8 ม.), `theme` (ใช้เลือกของตกแต่ง) |
| Door / Stairs | `id`, `a`, `b` (ห้องสองฝั่ง), `kind` = `door` หรือ `stairs`, `open` (เริ่มเปิดหรือไม่) · ห้องที่เชื่อมกันคือ "ห้องข้างเคียง" |
| Panel | `panelRoom` ห้องที่ Panel อยู่ |
| จุดเริ่ม | `startRoom` ห้องที่ตัวละครยืนตอนเริ่ม |

**สายพ่วง (R13 ใหม่):** ลากไปได้เฉพาะห้องที่เชื่อมด้วย `door` (ข้าม Stairs ไม่ได้ ปรับด้วย `cordThroughStairs`)

**ด่าน 1–4 เป็นชั้นเดียวทั้งหมด** · Stairs รองรับในข้อมูลและซิม แต่ไม่มีด่านไหนใช้ในแจมนี้

### 2.2 ตัวละครผู้เล่น

| หัวข้อ | กฎ |
| --- | --- |
| การสั่ง | คลิกวัตถุ (ปลั๊ก เครื่อง Panel Door) → ตัวละครเดินไปห้องนั้นตามทางสั้นที่สุด แล้วทำ · คลิกพื้นห้อง = เดินไปเฉยๆ |
| คิวการกระทำ | สูงสุด `actionQueueSize` (ค่าเริ่ม **3**) แสดงเป็นไอคอนลำดับเหนือหัว คลิกขวาที่ไอคอนเพื่อยกเลิก · Shift+คลิก = ต่อคิว · คลิกธรรมดา = ล้างคิวแล้วสั่งใหม่ |
| เวลาเดิน | `ticks = round(ระยะทางระหว่างกลางห้อง ÷ walkSpeed × 10)` · walkSpeed **3 ม./วิ** (ห้อง 4 ม. ≈ 1.3 วิ) · Stairs +**20 tick** · Door ที่ปิด +**5 tick** (เปิดแล้วค้างเปิดไว้) |
| เวลาทำ | ทุกการกระทำ +**3 tick** (`interactTicks`) |
| ระหว่างหยุดเวลา | สั่งและแก้คิวได้ ตัวละครไม่ขยับ |
| ช่วงวางแผน (N6) | เสียบ ถอด วาง/ถอดสายพ่วง **และเปิดสวิตช์ล่วงหน้า** ได้ทันทีทุกห้อง ไม่ต้องเดิน · สับเบรกเกอร์ไม่ได้ |
| ทำไม่ได้ตอนถึง | (เช่น ปลั๊กถูกใช้ไปแล้ว) → `CommandRejected` ตอนถึง ข้อความตาม 3.5 ของ v1.0 แล้วทำงานถัดไปในคิว |
| เปิด/ปิด Door | คลิก Door → เดินไปห้องใดห้องหนึ่งของ Door แล้วสลับ |

**ตัวละครอยู่ในซิม (`Trouble.Sim`) ไม่ใช่ใน View** — ดู `docs/architecture/adr-0001-character-and-sight-in-sim.md`

### 2.3 Sight

| กฎ | รายละเอียด |
| --- | --- |
| V1 ห้องที่เห็น | ห้องที่ตัวละครอยู่ + ห้องที่เชื่อมด้วย `door` ที่ **เปิด** ลึก `sightDepth` ทอด (ค่าเริ่ม **1**) · Stairs ไม่ให้การมองเห็น (`sightThroughStairs` = false) |
| V2 ตอนเดิน | ตัวละคร "อยู่" ห้องปลายทางเมื่อผ่านกลาง Door (ครึ่งทางของช่วงนั้น) |
| V3 ช่วงวางแผน | เห็นทั้งบ้าน (ตอนเช้า ทุกอย่างยังนิ่ง) |
| V4 ห้องที่ไม่เห็น | มืดลง เห็นโครงห้อง ปลั๊ก และชื่อห้องเสมอ (คนในบ้านรู้ว่าปลั๊กอยู่ไหน) · **ไม่เห็น** สถานะเปิด/ปิดของเครื่อง และใครใช้อะไร · แสดง "ภาพที่เห็นล่าสุด" เป็นเงาจาง 30% พร้อมเวลาที่เห็นล่าสุด |
| V5 HUD | แถบโหลดของวงจรบนการ์ดเบรกเกอร์แสดงเสมอ (`breakerHudMode` = `Always`) ปรับเป็น `AtPanelOnly` ได้ |
| V6 | ซิมทำงานเหมือนเดิมทุกห้อง Sight เป็นแค่ข้อมูลที่ผู้เล่นได้รับ |

### 2.4 การเผยผังสายไฟ (R16′ แทน R16)

ปลั๊กถูกเผยเมื่อในหนึ่ง tick ครบทั้ง 3 ข้อ:
1. ห้องของปลั๊ก **มองเห็นอยู่**
2. เครื่องบนปลั๊ก **เปิดสวิตช์อยู่**
3. เบรกเกอร์ของวงจรของปลั๊ก **OFF**

แปลว่า "เห็นด้วยตาว่าเครื่องเปิดอยู่แต่ไม่มีไฟ" · เดินเข้าห้องทีหลังขณะเบรกเกอร์ยัง OFF ก็เผยได้ · `revealRequiresSight = false` → กลับไปใช้ R16 เดิม

**ผลต่อดีไซน์:** ท่ามาตรฐานจะกลายเป็น เสียบโคมไฟ → เปิด Door ระหว่างห้องนั้นกับห้อง Panel → ยืนที่ Panel แล้วสับทีละตัว · การเผยไม่กระทบผลแพ้ชนะ

### 2.5 การแจ้งเตือน

**กติกาหลัก: การแจ้งเตือนต้องไม่บอกผังสายไฟ** (ห้ามบอกว่าห้องไหนอยู่วงจรที่กำลังเกิน)

| แจ้งเตือน | ที่ไหน | เงื่อนไข |
| --- | --- | --- |
| โอเวอร์โหลด | การ์ดเบรกเกอร์ (HUD) + ไอคอนบน Panel ในฉาก | `OverloadStarted` · **ไม่** แสดงบนห้อง |
| Request ใกล้เดดไลน์ | ไอคอนหน้าเจ้าของบนห้องของ Request | เหลือ < 5 วิ |
| ถูกขัดจังหวะ | "!" + คำพูดเจ้าของ เช่น `Kid: MY SAVE!` | `ApplianceInterrupted` ของเครื่องที่มี Request |
| Routine ใกล้เริ่ม | ไอคอนหน้าเจ้าของบนห้องของ Routine + ไทม์ไลน์ | < 3 วิ |
| ตู้เย็นไม่มีไฟ | ไอคอนตู้เย็นบนห้องครัว + ตัวนับถอยหลัง | ตลอดที่ไม่มีไฟ |

ไอคอนบนห้องที่อยู่นอกจอ (ตอนซูมเข้า) แสดงเป็นลูกศรที่ขอบจอ คลิก = กล้องเลื่อนไปห้องนั้น (ตัวละครไม่ขยับ)

### 2.6 กล้อง

| หัวข้อ | ค่าเริ่ม |
| --- | --- |
| โปรเจกชัน | Perspective FOV **20°** มองตรงหน้าบ้าน · ปรับเป็น Orthographic ได้ |
| ซูม | ล้อเมาส์ ซูมเข้าหาตำแหน่งเมาส์ ทีละ 15% นุ่ม 0.15 วิ · ไกลสุด = ทั้งบ้าน + ขอบ 10% · ใกล้สุด = ห้อง 4 ม. กว้าง 60% ของจอ |
| แพน | ลากเมาส์กลาง หรือ WASD / ลูกศร · จำกัดในกรอบบ้าน · ขอบจอเลื่อน **ปิด** |
| ทางลัด | `F` ตามตัวละคร (สลับ) · `Home` ดูทั้งบ้าน · ดับเบิลคลิกห้อง = ซูมไปห้องนั้น |
| ระยะไกล | ซูมออกเกิน 60% ปลั๊กและเครื่องสลับเป็นไอคอน UI ขนาดคงที่ |

`R` = เริ่มใหม่ · `Space`/`P` = หยุด/เดิน · `Esc` = เมนู · `F1` = แผงปรับค่า (ไม่ชนกัน)

### 2.7 Panel

- วัตถุ 3D ในห้อง `panelRoom` · คลิกที่ Panel หรือการ์ดเบรกเกอร์ใน HUD → ตัวละครเดินไป Panel แล้วสับ (เข้าคิว)
- ด่าน 1: Panel อยู่ในครัว (สอนโดยไม่ต้องเดิน) · ด่าน 2 ขึ้นไป: อยู่ปลายบ้าน การเดินไป Panel คือต้นทุนของการวินิจฉัย

### 2.8 กฎที่เปลี่ยน

| รหัส | เดิม | ใหม่ |
| --- | --- | --- |
| R3 | โหลด ≤ ความจุ 1 tick → ตัวนับเป็น 0 | ตัวนับ **+1** ต่อ tick ที่โหลด > ความจุ · **−1 ทุก `overCoolEvery` tick** (ค่าเริ่ม **3**) ที่ไม่เกิน (ไม่ต่ำกว่า 0) · ครบ `overTripTicks` (**10**) → trip |

### 2.9 ลำดับใน 1 tick (แทน 3.4)

```
Step():
  1. ใช้คำสั่งในคิวคำสั่ง (คำสั่งผู้เล่น = เพิ่ม/ล้างคิวการกระทำของตัวละคร)
  2. ตัวละคร: ถ้ากำลังเดิน เดินหน้า 1 tick · ผ่านครึ่ง Door -> เปลี่ยนห้อง
     ถึงที่หมายและนับ interactTicks ครบ -> ทำการกระทำ (ตรวจกฎ 3.5 ตอนนี้) -> เริ่มงานถัดไปในคิว
  3. Routine (เดิมข้อ 2)
  4-8. เหมือนเดิมข้อ 3-8 (โหลด, วงจร [กฎตัวนับ 2.8], เบรกเกอร์หลัก, ขัดจังหวะ, ความคืบหน้า, ตู้เย็น)
  9. Sight: คำนวณห้องที่เห็น -> เผยปลั๊กตาม R16′ -> อัปเดตภาพที่เห็นล่าสุด
 10. now += 1
 11. แพ้ ลำดับสาเหตุ: ตู้เย็น -> เดดไลน์ -> หมดวัน
 12. ชนะ
```

**เปราะบางหลบใน tick เดียวไม่ได้:** ถ้าเครื่องเปราะบางเสียไฟเพราะคำสั่ง (ปิดสวิตช์ ถอด ย้าย) ให้ตั้งธง "ไฟหาย" ตั้งแต่ตอนใช้คำสั่ง ไม่ใช่รอเทียบในข้อ 6 (กันการ ปิด→เปิด ใน tick เดียวแล้วเซฟไม่หาย)

### 2.10 สคีมา JSON ที่เพิ่ม

```json
{
  "startRoom": "kitchen",
  "panelRoom": "laundry",
  "rooms": [
    { "id": "kitchen", "name": "Kitchen", "floor": 0, "x": 0, "width": 6, "theme": "kitchen" }
  ],
  "doors": [
    { "id": "D1", "a": "kitchen", "b": "living", "kind": "door", "open": false }
  ],
  "sockets": [
    { "id": "K1", "room": "kitchen", "circuit": "A", "assumed": "", "revealed": true, "pos": 0.25 }
  ],
  "routines": [
    { "owner": "Grandpa", "appliance": "heater", "socket": "L1", "startSec": 20, "durationSec": 20 }
  ],
  "rulesOverride": [ { "key": "sightDepth", "value": "1" } ],
  "scenarios": [
    { "name": "pump-breaker", "expect": "notFasterThanReference", "commands": [] }
  ]
}
```

- `pos` = ตำแหน่งปลั๊กแนวนอนในห้อง 0..1 (ไม่มี = เรียงห่างเท่ากัน)
- `rulesOverride` = ค่าใดๆ จาก `rules.json` ที่ด่านนี้ใช้ต่างจากค่ากลาง · เป็น **รายการ key/value** (value เป็นข้อความ) เพราะ `JsonUtility` อ่าน object ที่ key ไม่ตายตัวไม่ได้ และแยก "ไม่ได้ใส่" กับ "ใส่ 0" ไม่ออก
- `scenarios` = สถานการณ์ทดสอบเพิ่มเติมที่ Run Sim รันทุกครั้ง (ทางแก้ทางเลือก กับดัก ปั๊ม) พร้อมผลที่คาดหวัง
- คำสั่งใน `reference` เพิ่ม `move(a=ห้อง)` และ `door(a=Door)` · คำสั่งหลัง tick 0 = "สั่งตอนนี้" ตัวละครเดินไปทำเอง
- ด่านที่ไม่มี `rooms[].x/width/floor` หรือ `doors` → สร้างอัตโนมัติ: ชั้นเดียว กว้าง 6 ม. Door เปิดระหว่างห้องที่ติดกันในลำดับ (ไฟล์ v1.0 จึงโหลดได้ทันที)

## 4. เครื่องมือ: ปรับได้ทุกอย่าง

### 4.1 ขอบเขต

**ปรับได้โดยไม่แก้โค้ด:**

1. ค่ากฎทุกตัว (tick, ตัวนับโอเวอร์โหลด, การเดิน, Sight, คิว, สายพ่วง, ช่วงวางแผน, การเผย) → `rules.json` + `rulesOverride` รายด่าน
2. เครื่องใช้ไฟฟ้าทั้งหมด (ชื่อ โหลด เปราะบาง ป้ายสั้น ขนาดในโลก) → `catalog.json`
3. ด่านทั้งหมด (บ้าน วงจร ปลั๊ก Request Routine ทางแก้ สถานการณ์ทดสอบ) → Level Editor
4. **ข้อความในเกมทั้งหมด** (หมวด 4.3 และ 3.5 ของ v1.0, ชื่อปุ่ม, คำพูดครอบครัว) → `strings.json`
5. สี กล้อง ขนาด UI เสียง ความเร็วแอนิเมชัน → `TrippedViewConfig`
6. อาร์ต: วางไฟล์ตามชื่อแล้วใช้ได้ทันที

**ยังต้องเขียนโค้ด:** กฎชนิดใหม่ และวัตถุชนิดใหม่ (เช่น โซลาร์เซลล์)

### 4.2 ไฟล์ค่าปรับ

| ไฟล์ | เจ้าของ | ชั้น | เนื้อหา |
| --- | --- | --- | --- |
| `Assets/TRIPPED/Resources/Config/rules.json` | A | Sim | `ticksPerSecond` · `overTripTicks` · `overCoolEvery` · `breakerToggleResetsCounter` · `walkSpeed` · `interactTicks` · `doorOpenTicks` · `stairsTicks` · `sightDepth` · `sightThroughStairs` · `revealRequiresSight` · `cordThroughStairs` · `actionQueueSize` · `planningIsFree` · `breakerHudMode` |
| `Assets/TRIPPED/Resources/Config/catalog.json` | A | Sim + View | เครื่องใช้ไฟฟ้า: `id` `name` `load` `fragile` `shortLabel` `worldHeight` (แทน `ApplianceCatalog` ในโค้ด) |
| `Assets/TRIPPED/Resources/Config/strings.json` | A | View | ข้อความทั้งหมด key → ข้อความ (รองรับ `{placeholder}`) |

### 4.3 Level Editor (`Tools > TRIPPED > Level Editor`) — เจ้าของ A

| แท็บ | ทำอะไร |

- **Record** บันทึกคำสั่งที่เล่นมือเป็น `reference` หรือ `scenarios` (A เตรียม API ให้)
